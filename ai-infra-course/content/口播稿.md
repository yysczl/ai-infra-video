## S29 一次推理请求的完整流程

预计 02:02

### S29.0 认出开头的第 05 条晚餐请求

回到开头的第五条请求。「推荐一道晚餐」比前四条晚看到回答。现在可以沿着它找原因。

### S29.4 沿 API 路径验证输入和权限

请求到达时，前四条已经占满了这次可用的缓存预算。第五条得先留在队列里。

### S29.1 缓存释放后让第 05 条离开队列

第一条答完，归还了足够的缓存。调度器这才把第五条从队列交给 GPU。

它的输入在这张示意图里切成四个 Token。

等这条请求答完，右边没被保留的缓存就还给池子，留给后来的请求。

### S29.3 跟踪上线前的参数交付

把视角拉远，这条请求到达之前，模型已经训练好，部署好的副本也已经加载了参数。

### S29.12 跟踪第 05 条经过接口和调度

第五条沿橙线进来，在接口后面的队列多等了一段，之后才到 GPU 处理输入。

开始生成之后，Decode 每轮读缓存，算下一个 Token。
